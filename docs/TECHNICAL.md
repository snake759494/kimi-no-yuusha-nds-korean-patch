# 기술 문서

## 롬 구조
- NitroFS 파일 시스템을 ndspy로 읽고 씁니다. 대사는 `_Data/Event`, `_Data/Script` 아래 `.dat` 파일에 있고, 대부분은 여러 서브 스크립트를 묶은 팩입니다(`tools/pack.py`).
- 일부 `.dat`는 팩이 아니라 스크립트 하나로 되어 있어 통째로 해석합니다.

## 텍스트 원천
| 원천 | 형식 | 처리 |
| --- | --- | --- |
| 이벤트·필드 스크립트 | 명령 바이트열 + 길이(1바이트) 접두 Shift-JIS 문자열 | `evscript.py`로 명령 단위 해석 후 문자열 교체(길이 변경 가능). 해석에 실패하는 서브 스크립트 50개는 `rescue.py`가 문자열 접두 패턴으로 위치를 찾아 교체 |
| 데이터(아이템·마물·지명·의뢰) | 길이 접두(1·2바이트) 목록 / 고정 길이 칸 | `datafmt.py`, `data_patch.py` |
| 전투 보스 대사 | `Enemy_*.dat` 안 20바이트 고정 칸 | 칸 길이 안에서 교체 |
| 실행 코드(arm9) | Shift-JIS | 원래 길이 안에서 제자리 교체(`arm9_patch.py`) |
| 게임기 메뉴 제목 | 배너 UTF-16LE 6개 언어 칸 | 0x240부터 교체 후 CRC16 재계산 |

## 한글 인코딩·글꼴
- 사용된 한글 음절만 모아 Shift-JIS 2바이트 코드에 대응시키고(`common.py`의 `Enc`), 게임 폰트(NFTR)의 해당 글리프를 Galmuri11 비트맵으로 덮어씁니다.
- 조사는 앞 글자 받침에 따라 자동 선택합니다(이름이 바뀌는 자리용).

## 그림 글자
- NCGR/NCBR 타일 + NCLR 팔레트 + NCER 셀/NSCR 맵을 RGBA로 풀어 원본 글자를 지우고(inpaint·행 단위 배경 복원) 한글을 렌더링한 뒤 원래 팔레트로 양자화해 다시 넣습니다(`gfx.py`, `gfxpatch.py`, `gfx_build.py`).
- 장 번호 간판은 셀 단위로 「제/화/최종」 글자를 새로 그리고, 상태 메뉴 능력치 이름은 4bpp 글자 타일 시트에 직접 씁니다.
- 튜토리얼 그림(EventSubBG_01~36)은 영역별 명세(밝은 글자·어두운 글자·큰 제목 등 스타일)로 처리합니다(`tutor.py`).
- 타이틀 로고는 일본어 부분만 지우고 「너의 용사」를 원본 색·외곽선으로 얹었으며 영어 KIMINO YUSHA는 유지했습니다.
